# Simple OpenFPM example

A minimal OpenFPM program that demonstrates the basic usage of the distributed
vector `vector_dist`: creating particles in a 2D periodic domain, assigning
random positions and scalar/vector/tensor properties, redistributing them
across MPI ranks, reducing a counter, and writing the result to VTK files.

## Files

- `example/main.cpp` — the example source code (2D random particles)
- `example/main3d.cpp` — a 3D example that samples points on a **torus**, a
  beautiful 2-manifold embedded in 3D space, colored with a rainbow gradient
  around the ring and with surface-normal vectors; it writes a gradual
  "forming" animation as a ParaView time series (`torus.pvd`)
- `example/Makefile` — builds and runs the examples

## Prerequisites

OpenFPM must be installed (from source, pre-built binary, or Docker). The
example needs at least:

- A C++ compiler (gcc/g++ or clang)
- MPI (e.g. Open MPI)
- METIS or ParMETIS
- Boost
- The OpenFPM headers/libraries

See https://openfpm.mpi-cbg.de/building/ for the full dependency list and build
instructions.

## Compile and run (terminal commands)

The instructions below assume you built OpenFPM from source and installed the
dependencies into `$PREFIX_DEPENDS` and OpenFPM into `$PREFIX_OPENFPM` (adjust
the paths to match your installation).

### 1. Generate the `example.mk` file

OpenFPM ships a helper script that produces the compiler/linker flags needed to
build example programs. Run it once and place the result next to the Makefile:

```bash
cd /path/to/openfpm
./script/create_example.mk.sh $PREFIX_DEPENDS $PREFIX_OPENFPM
mv example.mk /path/to/fpm/example
```

If you used the pre-built binary or Docker image instead, generate `example.mk`
according to that distribution's instructions (or set the include/lib paths
manually in `example/Makefile`).

### 2. Build the example

```bash
cd /path/to/fpm/example
make
```

This compiles `main.cpp` into the `main` executable using the flags from
`example.mk`.

> **Note (this machine):** the `example.mk` generated by OpenFPM was edited to
> add the system MPI include/library paths (`/usr/lib/x86_64-linux-gnu/openmpi`)
> and the `-lmpi -lmpi_cxx` libraries, and the `Makefile` uses `g++` (not `cc`)
> so that `libstdc++` is linked. These edits are already applied in this folder.

### 3. Run the example

```bash
make run
```

which is equivalent to:

```bash
mpirun -np 2 ./main
```

The program prints the total particle count and writes `particles*.vtp` files
(one per MPI rank, plus a `particles.pvtp` collection) that you can open in
ParaView.

### 3b. Run the 3D torus (beautiful manifold) example

```bash
make main3d
make run3d
```

which is equivalent to:

```bash
mpirun -np 2 ./main3d
```

This writes a **time series** of VTK file sets plus a ParaView collection file:

- `torus.pvd` — the collection that ties every time step together with its time
  value (**open this one in ParaView**)
- `torus_<k>.pvtp` — the per-step collection (k = 0 .. 59), now carrying
  `TimeValue` metadata
- `torus_<rank>_<k>.vtp` — the per-MPI-rank geometry for step k

Each frame reveals a larger arc of the main ring, so playing them back forms the
torus little by little. The particles are pre-generated once and sorted by the
ring angle, so the revealed arc grows smoothly and the particles already shown
do not jump around between frames.

**Watching the "forming" animation in ParaView:**

1. Open `torus.pvd` (**not** a single `.pvtp`). Because the `.pvd` provides a
   real time axis, ParaView loads all 60 time steps with timesteps 0 … 59.
2. Press the **Play** button (or use the Animation toolbar) to watch the torus
   form frame by frame.
3. Color by the `color` scalar to see the rainbow gradient around the ring, and
   add **Glyphs** using the `normal` vector to visualize the surface
   orientation.

> Opening a single `.pvtp` instead of the `.pvd` is the usual cause of the Play
> button either doing nothing or appearing to run "really fast": the step files
> are seen as unrelated datasets with no time information, so no usable time
> axis is built.

> Tip: to make the animation loop smoothly, set the animation mode to "Snap to
> timesteps" and enable looping in the Animation view.

> **Note (this machine):** OpenFPM was built from source with the optional
> `numerics` module **disabled** (`-DENABLE_NUMERICS=OFF`) to avoid the
> Eigen/minter/PETSc dependency chain. The runtime libraries must be on
> `LD_LIBRARY_PATH` and MPI on `PATH`. A convenient run command is:
>
> ```bash
> export PATH="$HOME/openfpm_dependencies/MPI/bin:$PATH"
> export LD_LIBRARY_PATH="$HOME/openfpm_dependencies/METIS/lib:$HOME/openfpm_dependencies/PARMETIS/lib:$HOME/openfpm_dependencies/BOOST/lib:$HOME/openfpm_dependencies/HDF5/lib:$LD_LIBRARY_PATH"
> mpirun -np 2 ./main
> ```

### 4. Clean

```bash
make clean
```

## Using Docker (alternative, no local build)

If you prefer the official Docker image, mount this folder and build inside the
container:

```bash
docker run --rm -v "$PWD/example":/work -w /work openfpm/openfpm:latest \
  bash -c "./path/to/script/create_example.mk.sh \$PREFIX_DEPENDS \$PREFIX_OPENFPM && mv example.mk . && make run"
```

(Adjust the image tag and paths to your Docker setup; see
https://openfpm.mpi-cbg.de/docker/.)
